# Обновление игры до версии 8

В меню добавлены шесть уровней. Скорость и время берутся из одного редактируемого JSON-блока в `public/index.html`. Следующий уровень открывается после победы и записывается для обоих игроков в Durable Object; друг может войти только в открытый ему уровень. В комнате у обоих одинаковая трасса и параметры. Прежние механики сохранены.

## Что загрузить в GitHub

1. Распакуйте архив и откройте папку `tow-dash`.
2. В существующем репозитории замените следующие файлы. Пути считаются от корня, где лежит `wrangler.jsonc`:

   | Файл | Что меняется |
   |---|---|
   | **`public/index.html`** | Список уровней, их скорости и длительность; блок `level-config` |
   | **`public/levels.js`** | Чтение и проверка списка уровней |
   | **`public/app.js`, `public/style.css`** | Выбор уровня в меню, блокировка закрытых уровней и отображение прогресса |
   | **`public/engine.js`, `public/render.js`** | Версия 8: длительность, скорость и координаты препятствий для выбранного уровня |
   | `public/feedback.js` (добавлен в версии 3) | Вибрация старта, смерти, возрождения; собственный отсчёт |
   | `public/_headers` | Проверка актуальности нового JS-файла при открытии |
   | **`worker/index.js`** | Проверка уровней, общий уровень комнаты и сохранение побед обоих друзей |
   | `tests/engine.test.js`, `tests/render.test.js`, `tests/network.mjs` | Проверки параметров, трасс и сетевых ограничений |
   | `tests/feedback.test.js` | Проверки таймера и вибрации |
   | `README.md`, `QA.md`, `UPDATE.md`, `docs/` | Инструкция, результаты проверок и снимки |

   Проще заменить целиком `public/`, `worker/`, `tests/` и три файла документации. Это также принесёт изменения предыдущих версий, если вы их пропустили. Обязательно добавьте **новый файл `public/levels.js`** и опубликуйте Worker вместе с `index.html`: оба читают одни настройки. `package.json`, зависимости, шрифт и конфигурация Cloudflare не менялись.

3. Через сайт GitHub: **Add file → Upload files**, загрузите папки и файлы, затем **Commit changes** в ветку публикации. Дополнительную вложенную папку `tow-dash` создавать не нужно. При обновлении со старой версии обязательно добавьте `public/feedback.js`: без него клиент не запустится.
4. **Оставьте свой настроенный `wrangler.jsonc`.** Имя Worker, `BOT_USERNAME`, `REQUIRE_TELEGRAM_AUTH`, привязка `ROOMS`, класс `GameRoom` и миграция `v1` сохраняются. Новые Cloudflare-привязки и миграции не нужны. Секрет `TELEGRAM_BOT_TOKEN` повторно вводить не нужно.

## Как опубликовать на Cloudflare

Клиентские файлы и `worker/index.js` должны попасть в один деплой.

- **Workers Builds, подключённый к GitHub:** выберите ваш Worker и проверьте Build settings: правильный репозиторий, ветка с последним коммитом, корневая папка проекта. Для этого проекта Build command — `npm test`, Deploy command — **`npx wrangler deploy`**. Дождитесь успешной публикации именно последнего коммита.
- **Ручной GitHub Actions:** **Actions → Deploy to Cloudflare → Run workflow**, выберите ветку с обновлением. Workflow проверок при push сам по себе игру не публикует.
- **С компьютера, из папки проекта:** `npm ci`, затем `npm run deploy`. Потребуется ранее настроенный вход в Cloudflare или токен публикации.

В этом проекте **`npm run build` выполняет только dry run**, то есть проверку сборки без публикации. Если в Cloudflare команда Deploy заменена на `npm run build`, на игровом адресе останется старая версия.

После успешного деплоя откройте **свой игровой адрес**, добавив в конце `/api/config`. В JSON должно быть:

```json
"version": 8
```

Это поле присутствует рядом с настройками бота. Если версия другая или поля нет, по этому адресу ещё работает старый сервер. Если вместо JSON открылась HTML-страница или ошибка 404, проверьте, что открыли адрес Worker с сервером комнат.

Рядом с `version` в `/api/config` должен быть массив `levels` из шести записей. Затем проверьте `/engine.js`: в начале файла должно быть `VERSION: 8`. Откройте `/levels.js`: он должен отдаваться как JavaScript. Закройте Mini App **на обоих устройствах**, откройте заново и создайте новую комнату. Старые клиенты получают просьбу обновиться.

## Если Cloudflare снова не обновляет игру

1. Сравните последний коммит GitHub с коммитом в истории сборок вашего Worker. При разных коммитах проверьте подключённую ветку и папку проекта.
2. Откройте **Deployments → View Build History**, выберите нужную сборку. При ошибке посмотрите её журнал; повторный запуск — **Retry build**. Успешная проверка тестов отдельно от публикации недостаточна.
3. Если в журнале ошибка имени, `name` в вашем `wrangler.jsonc` должен совпадать с именем Worker в Cloudflare. Если не найдена точка входа, проверьте корневую папку и наличие `worker/index.js`.
4. Проверьте именно production-адрес, который указан у BotFather. Успешная preview-сборка другой ветки не меняет production. Если оба файла и API показывают новую версию, полностью переоткройте Mini App на обоих устройствах.

Основание настроек: [Workers Builds configuration](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/) и [Troubleshooting builds](https://developers.cloudflare.com/workers/ci-cd/builds/troubleshoot/).

## Как проверить новые механики

| Механика | Что должно происходить |
|---|---|
| Смерть друга | Вы продолжаете бег без чужого отсчёта. Погибший видит свои 6 секунд |
| Башня / двойной блок | Прыгните в жёлтое кольцо: оно автоматически подбросит выше препятствия. Обычный прыжок без кольца недостаточен |
| Лестница | Прыгайте по отдельным белым столбам над шипами; жёлтые кольца помогают пройти длинные пролёты и высокий центральный пик. Жёлтая метка и «ПРЫГАЙ» показывают момент прыжка. Не касайтесь боковых граней и шипов |
| Короткие связки | Промежутки иногда заметно короче базового ритма. Даже у близких групп остаётся проверенное время для приземления и следующего прыжка |
| Красная ловушка | Бегите по земле через красный блок. При попытке перепрыгнуть он выдвигает высокий шип, затем убирает его обратно |
| Босс | Трижды случайно после второй минуты по 16 секунд; 16 выстрелов с промежутком 0,9 секунды. Низкие красные пули перепрыгивайте, белые проходят выше обычного прыжка; после боя перепрыгните оставшийся блок |
| Полёт | По одному разу в каждую минуту, 12 секунд. Широкие камеры чередуются с узкими участками. Кто сверху и снизу — случайно. Зажали — вверх, отпустили — вниз; стен касаться нельзя |
| Переход | После большинства полётов или перед ними через 1,5 секунды происходит переворот дороги |
| Возрождение | Над шипами куб появляется на подходящей ступени; в лабиринте держится безопасного маршрута до первого ввода |
| Выход из полёта | Возвращаются кубы, общая дорога и верёвка; шестиминутный таймер не сбрасывается |
| Вибрация | На поддерживаемом устройстве внутри Telegram: старт, ваша смерть, ваше возрождение. Смерть друга не вызывает сигнал |
| Звёзды | Редкие белые точки медленно двигаются и гаснут. Под платформой их нет |

Физическая отдача зависит от устройства и настроек Telegram; браузерная проверка подтвердила вызовы API, но не заменяет запуск на телефоне. Код комнаты по-прежнему вводится встроенными кнопками без системной клавиатуры.

## Первая установка

Загрузите всё содержимое `tow-dash` в корень нового репозитория и выполните раздел запуска в `README.md`. Сервер комнат использует Cloudflare Workers + Durable Objects. Инструкция выше обновляет уже работающий проект.
