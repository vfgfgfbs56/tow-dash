# С ПРИЦЕПОМ

Горизонтальная Telegram Mini App: два игрока, одна случайная трасса, шесть минут до финиша. Чёрный фон и локальный `PressStart2P-Regular.ttf` с кириллицей. Проект для **GitHub → Cloudflare Workers**. Отдельный VPS не нужен. Обновление существующей установки описано в [UPDATE.md](UPDATE.md).

## Что работает

- Комнаты с четырёхзначным кодом, приглашение ссылкой, два участника через WebSocket.
- Каждый видит себя синим, друга красным. Координаты и порядок одинаковые у обоих; порядок выбирается случайно для каждой попытки.
- Отсчёт **5 секунд**, затем **6 минут игрового времени**. Старт **×2,0**, каждые **10 секунд +0,1**. Последние десять секунд идут на **×5,5**; на финише скорость больше не растёт.
- Шипы, двойные шипы, блоки и вращающиеся пилы в случайных группах. Каждую минуту растут количество и высота препятствий, сокращаются промежутки. В начале группа содержит 1–2 препятствия, в последнюю минуту — 4–5. У новой попытки новый случайный seed.
- Высокие башни с жёлтым кольцом перед ними. Обычного прыжка недостаточно: нужно в прыжке коснуться кольца. Оно автоматически даёт второй, более сильный импульс. Повторное нажатие не требуется; каждый участник может отдельно использовать одно и то же кольцо.
- Ложные фигуры с маленьким пустым ромбом и прерывистым основанием. Через них нужно пробегать по дороге. Прыжок над фигурой убивает, даже если куб выше её вершины. Подсказка прыжка перед такой фигурой не появляется.
- **Шесть полётных участков по 12 секунд**, по одному в каждой минуте. Начало случайное между 10-й и 42-й секундами соответствующей минуты, поэтому каждый маршрут заканчивается до следующей минуты. В начале маршрута игроки случайно распределяются между верхним и нижним коридорами. Удерживайте экран, пробел, W или ↑, чтобы лететь вверх; отпускайте, чтобы лететь вниз. Стены смертельны. Коридоры с зигзагами и расширениями становятся уже от минуты к минуте. Верёвка убирается при входе и возвращается после выхода; цвета игроков остаются локальными.
- Случайные перевороты дороги: возможный первый через 20–30 секунд, следующие кандидаты через 26–36 секунд. Переходы рядом с полётными участками пропускаются. Оба игрока вместе переходят на потолок, затем обратно; гравитация направлена к текущей дороге. Во время переноса на 0,65 секунды прыжок блокируется. Рядом с переворотом нет препятствий. Фиолетовый ромб заранее обозначает переход.
- Прыжок касанием экрана, пробелом, W или ↑. На потолке куб прыгает вниз. Нельзя летать повторными нажатиями: прыжок только с дороги, буфер ввода 120 мс.
- Маленькая синяя метка перед группой мягко пульсирует в безопасное время прыжка именно вашего куба. При настройке «уменьшить движение» подсветка постоянная. Подсказка не нажимает прыжок за игрока.
- Поле игры занимает весь экран без наружной рамки, верхней центральной подписи, нижней инструкции, кнопок выхода и полного экрана. Во время бега сверху остаются скорость и время; отсчёт старта и возрождения сохранены. Запрос полного экрана происходит автоматически при запуске игры.
- Код комнаты вводится только собственной цифровой клавиатурой или физическими клавишами. Поле отображения не редактируемое: системная клавиатура не вызывается. Убрано копирование кода; приглашение через Telegram остаётся. Заблокированы выделение, контекстное меню, копирование, жесты масштаба и прокрутка игрового поля.
- При гибели куб рассыпается, верёвка сворачивается и исчезает. Напарник продолжает бег и **не видит таймер возрождения друга**. Только погибший видит собственный отсчёт. Через **6 секунд** куб собирается обратно; верёвка возвращается. После появления действует видимый защитный контур минимум **1,25 секунды**, чтобы не появиться внутри препятствия. В полёте участник возвращается в центр своего коридора.
- Вибрация через Telegram `HapticFeedback`: начало матча — `medium`, собственная смерть — `error`, собственное возрождение — `success`. События друга не вызывают вибрацию; повторные сетевые снимки не дублируют сигнал. Сохранён короткий `light` при обычном нажатии прыжка. Вне Telegram игра работает без этих сигналов.
- Небольшие белые звёзды медленно дрейфуют, появляются и гаснут. На дороге они рисуются только над платформой; в полёте — внутри пустого пространства коридоров. При настройке «уменьшить движение» фон неподвижен.
- Если оба погибли одновременно, попытка закончена. Для победы достаточно одного живого участника на финише. Новую попытку в сетевой игре подтверждают оба.
- Потеря сети, сворачивание приложения или вертикальный экран ставят сетевой матч на паузу до 20 секунд. Это время не входит в шесть минут. Переподключение возвращает того же участника; после 20 секунд матч прекращается.
- Тренировка с обозначенным напарником-ботом, чтобы можно было попробовать игру одному.

Верёвка — визуальная эластичная связь. Она не тянет кубы и не изменяет траекторию прыжка. Игроки независимо прыгают, но бегут с общей скоростью; одиночный выживший плавно смещается к центру кадра. Если нужна именно физическая верёвка, ограничивающая расстояние, это отдельное изменение правил и генератора.

## Самый простой запуск: GitHub и Cloudflare в браузере

1. Распакуйте архив. Создайте репозиторий в GitHub и загрузите **содержимое папки `tow-dash` в корень репозитория**. На одном уровне должны оказаться `package.json`, `package-lock.json`, `wrangler.jsonc`, `public/`, `worker/`. Не загружайте `node_modules` и `.dev.vars`. При загрузке через веб-интерфейс отдельно проверьте наличие `.github/workflows/`; при необходимости создайте эти файлы через GitHub или загрузите проект с Git.
2. В Cloudflare откройте **Workers & Pages → Create application → подключение GitHub**, выберите репозиторий. Создавайте **Worker**, поддерживающий Durable Objects. Обычная статическая GitHub Pages или Pages Direct Upload не запускает комнаты.
3. Укажите имя Worker **`tow-dash`**, совпадающее с `name` в `wrangler.jsonc`. Если оно занято в вашем аккаунте, измените оба имени одинаково.
4. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Корневая папка | `/` (если файлы в корне) |
   | Build command | `npm test` |
   | Deploy command | `npx wrangler deploy` |
   | Ветка production | `main` |
   | Node.js | 22 или новее |

   Workers Builds устанавливает зависимости по `package-lock.json`. Отдельная папка результата сборки не нужна: статика берётся из `public`, сервер — из `worker/index.js`.
5. Нажмите Deploy. `wrangler.jsonc` создаёт привязку `ROOMS` и SQLite Durable Object `GameRoom` миграцией `v1`. Не удаляйте миграцию при последующих изменениях.
6. Откройте выданный Cloudflare HTTPS-адрес. Проверьте тренировку; затем откройте адрес на двух устройствах, создайте комнату на одном и введите её код на другом.

### Подключение к Telegram

1. В официальном **[@BotFather](https://t.me/BotFather)** создайте бота через `/newbot` или выберите своего. Сохраните токен у себя.
2. В Cloudflare у Worker откройте **Settings → Variables and Secrets**. Добавьте **секрет** `TELEGRAM_BOT_TOKEN` со значением токена. Не кладите токен в GitHub, HTML, JS или переписку.
3. В `wrangler.jsonc` измените `vars.BOT_USERNAME` на username бота **без `@`**. Для приложения только внутри Telegram задайте `vars.REQUIRE_TELEGRAM_AUTH` равным строке `"true"`. Изменения в репозитории должны быть опубликованы заново. Оставьте `"false"`, если хотите также разрешать гостевые матчи в обычном браузере. В обоих режимах переданный `initData` всегда проверяется, а не считается доверенным.
4. В BotFather: `/mybots` → ваш бот → **Bot Settings → Configure Mini App → Enable Mini App**. Укажите HTTPS-адрес Worker как URL главного Mini App. Названия пунктов могут зависеть от языка Telegram.
5. По желанию задайте кнопку меню через `/setmenubutton`, текст «Играть» и тот же URL.
6. Откройте бота в Telegram, запустите игру и поверните телефон. Telegram 8.0+ позволяет запросить полный экран и **зафиксировать уже текущую ориентацию**. Поэтому приложение сначала просит повернуть экран, затем фиксирует горизонталь. Старые клиенты получают такой же экран поворота без обещания аппаратной блокировки.
7. «Пригласить друга» открывает выбор получателя в Telegram. Ссылка имеет вид `https://t.me/USERNAME?startapp=room_1234`; ввод кода остаётся доступен вручную. Для этой ссылки нужно настроить **Main Mini App** у BotFather.

Ни бот, ни приложение не требуют отдельного постоянно запущенного процесса. Webhook для запуска через Main Mini App / кнопку меню не нужен. Ответы на произвольные сообщения боту и команда `/start` с текстовым ответом в этот проект не входят.

## Альтернатива: GitHub Actions

Уже добавлены проверки при push/PR и ручной workflow **Deploy to Cloudflare**. Если используете Workers Builds, второй механизм публикации можно не включать.

Для Actions добавьте в настройках репозитория **Settings → Secrets and variables → Actions**:

- `CLOUDFLARE_API_TOKEN`: токен Cloudflare с правами развёртывания Workers в нужном аккаунте; подойдёт соответствующий шаблон редактирования Workers. Ограничьте область своим аккаунтом.
- `CLOUDFLARE_ACCOUNT_ID`: ID этого аккаунта.

Запуск: **Actions → Deploy to Cloudflare → Run workflow**. Секрет Telegram задаётся в самом Worker, не в коде. После первого развёртывания добавьте его в Cloudflare. Автодеплой на push можно включить согласно комментарию в `deploy.yml`.

## Локальный запуск

Нужен Node.js 22+.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:8787`. Два независимых браузера или два устройства могут создать и соединить комнату. Вкладка должна оставаться видимой: её сворачивание включает паузу. Для проверки с телефона на одной Wi-Fi сети используйте LAN-адрес компьютера; Telegram production требует HTTPS.

```bash
npm test              # 50 полных трасс, полёт, кольца, ловушки, haptics, Telegram HMAC
npm run build         # Сборка Worker без публикации
npm run test:network  # Два реальных клиента; npm run dev должен уже работать
```

`npm run preview:static` открывает только локальную тренировку на порту 8080. Для сетевых комнат требуется Worker. Открытие `index.html` двойным щелчком через `file://` не поддерживается ES-модулями браузера.

## Как проверяется проходимость

Единый `public/engine.js` используется и клиентом, и сервером. Фиксированный шаг — **1/120 секунды**. Сервер принимает нажатие и отпускание управления, а не координаты, результаты или сообщения «я жив». На дороге нажатие запускает прыжок, в полёте состояние удержания задаёт направление.

Для каждой **целой обычной группы** генератор перебирает моменты прыжка и численно проверяет полную траекторию по общей формуле движения. Учитываются хитбокс куба, общая прямоугольная оболочка группы (включая зубья пил), запас по высоте и изменение скорости на границе каждой десятой секунды. Группа принимается, только если **для обеих позиций игроков** существует непрерывное окно безопасного начала прыжка. Иначе размеры уменьшаются; после 12 неудачных проверок кандидат пропускается. Показатель интервала ниже — время между расчётными центрами обычных групп; кандидаты у переворотов и полётных участков пропускаются. У башен оставлено больше места для разгона и приземления.

| Минута | Препятствий в группе | Интервал групп, с | Минимальное окно прыжка |
|---|---:|---:|---:|
| 1 | 1–2 | 1,40–1,80 | 200 мс |
| 2 | 2–3 | 1,25–1,55 | 190 мс |
| 3 | 2–4 | 1,13–1,38 | 180 мс |
| 4 | 3–4 | 1,02–1,26 | 170 мс |
| 5 | 3–5 | 0,95–1,12 | 160 мс |
| 6 | 4–5 | 0,90–1,02 | 150 мс |

Проверяется и полное пересечение группы обоими кубами: оно не должно попадать в защитный интервал от 1,3 секунды до переворота до 1,45 секунды после него. На потолке физика зеркально отражена относительно дороги, поэтому проверенные траектории сохраняются. Маркер берёт время из проверенного окна конкретной позиции игрока. Тесты проходят полные трассы прыжками как в середине, так и у краёв этих окон.

Для башни отдельно симулируются первый прыжок, контакт с кольцом, дополнительный импульс, пролёт над башней и приземление. Требуется окно не менее **120 мс** для каждого игрока; в проверке кольцо уменьшено, а башня увеличена на запас. Высота башни превышает предел обычного прыжка. Ложная фигура безопасна при `y ≤ 12` над дорогой; выше этого порога горизонтальное пересечение смертельно независимо от высоты фигуры. Промежутки между группами позволяют после предыдущего прыжка вернуться на дорогу.

Каждый полётный маршрут проверяется для обеих дорожек и обеих горизонтальных позиций с изменением управления **15 раз в секунду**. Генератор принимает маршрут только при запасе минимум 12 единиц между хитбоксом и стенами; неудачный вариант упрощается и проверяется заново. Стены и столкновения используют одну и ту же геометрию. Первые 0,55 секунды входят в общие 12 секунд и отведены на перенос в коридоры. Дорожные препятствия отсутствуют за 2 секунды до полёта и 1,6 секунды после него.

Эта проверка означает, что существует проходимая последовательность действий при заданной физике. Она не гарантирует прохождение человеком при любой задержке сети или случайных нажатиях. На большой скорости камера немного отдаляется, чтобы показывать больше трассы.

## Сетевая схема и ограничения

- Один `GameRoom` Durable Object на комнату, два WebSocket. Сервер рассчитывает игру; клиент предсказывает движение и сглаживает отрисовку между снимками состояния. Пакеты состояния отправляются примерно 15 раз/сек, симуляция идёт с фиксированным шагом 120 Гц.
- Во время матча таймер держит объект активным. В ожидании таймер выключен и соединения могут переходить в hibernation. Контрольная точка сохраняется раз в 5 секунд; при перезапуске инфраструктуры возможно возвращение к последней точке, а не перескакивание вперёд через препятствия.
- Неактивная комната удаляется через 30 минут; новая попытка обновляет срок. Повторный вход использует секретную сессию из `sessionStorage` этой вкладки. Токены сессий не включены в URL приглашения, пакеты состояния или имена игроков.
- Telegram-подпись HMAC и срок `auth_date` проверяются сервером; для нового входа принимаются данные не старше часа. Развёртывание без `REQUIRE_TELEGRAM_AUTH=true` намеренно допускает гостевой вход.
- Четыре цифры — удобный код, не секретная защита от угадывания. Это небольшая кооперативная игра без рейтинга, денежных операций и наград. На WebSocket установлен лимит частоты сообщений.
- Отдельный VPS не нужен, но Cloudflare предоставляет серверную часть и применяет лимиты своего тарифа. Активные комнаты используют вычисления, WebSocket и хранилище; проект не обещает неограниченную бесплатную нагрузку.
- Проверки не заменяют финальный запуск на двух реальных телефонах внутри Telegram после публикации. Здесь нет доступа к вашему Cloudflare-аккаунту и боту для такого запуска.

## Где менять параметры

| Файл | Назначение |
|---|---|
| `public/engine.js` | Физика, кольца, ловушки, генератор коридоров, скорость, возрождение |
| `public/render.js` | Кубы, башни, лабиринт, звёзды, верёвка, частицы, камера |
| `public/app.js` | Меню, ввод, комнаты, Telegram, переподключение |
| `public/feedback.js` | Личный таймер возрождения и вибрация Telegram |
| `public/style.css` | Чёрный интерфейс, размеры, горизонтальная адаптация |
| `worker/index.js` | Cloudflare API и серверная комната |
| `worker/auth.js` | Проверка подписи Telegram |
| `wrangler.jsonc` | Публикация, привязки, публичное имя бота |
